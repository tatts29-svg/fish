Run serially with the repository's Chromium harness. `PAGE` names the candidate, `STATE` an authorised private native record snapshot, and `OUT` a private evidence directory. Do not commit snapshots, instrumented copies or screenshots.

```sh
flock /tmp/gc500-browser.lock node tests/native_ring12431.cjs
flock /tmp/gc500-browser.lock node tests/native_pictures12431.cjs
```

`native_ring12431.cjs` creates a private copy with diagnostics for the closed ring implementation and a controlled empty projection. It checks the native departure projection, full pulse, steady dashed partial ring, reduced-motion painting, actual CSS mode visibility, parent iframe intersection, re-entry and the native empty-projection branch. Mode checks apply the same body classes used by3D/Fencing; they do not certify the3D scene renderer. The ring remains pointer-events:none; source tests separately preserve native icon/status logic.

`native_pictures12431.cjs` first opens the unmodified candidate and checks three loaded pictures in Demob and Find-it, with the third spanning the grid. It then opens a private observable copy to test the native cache. Synthetic cache entries apply budget pressure only in page memory; the original card is evicted while off-tab, queued invisible work is pruned, and native DOM/IntersectionObserver re-entry reloads all three pictures. There are no operational record edits or message sends.

Every session must have zero runtime errors, console errors and blocked operational write attempts. The harness allows only the existing Google basemap-session POST exception. These tests make no whole-application frame-rate or deployed-release claim.
