PRICING LIST - WHAT MUST NOT CHANGE
===================================

For whoever is handed the Pricing tab of Ampol_Master.xlsx to review -
or, on a laptop that has not yet run button 16, the old file
Ampol_ToolStore_Pricing.xlsx. Every rule here was read from the report
code on 03 Sep 2026 (suite v1.13).

The file
--------
  Name:      Ampol_Master.xlsx  (lives in Data\Editable; found by the
             pattern Ampol_Master*.xlsx - ampol_paths.find_data)
  Tab:       Pricing  - one of five tabs. The others are Read me,
             Descriptions, Gas serials and Radio serials; each of the
             data tabs feeds a report and must stay.
  Header:    row 1
  Size:      3,227 data rows under the header (about 3,230 rows)
  Layout:    a plain list - header row frozen, an autofilter, no Excel
             table, no merged cells, no title rows
  Legacy:    Ampol_ToolStore_Pricing.xlsx, sheet RENTAL_STOCK (the one
             and only sheet, an Excel table called Table1) - the same
             six headers and the same rows. Read only while there is
             no Ampol_Master.xlsx (ampol_master.locate). Button 16
             builds the tab from it, every row, values only, and parks
             it in Data\_Archive_workbooks - never deleted.

The six columns, exactly as the headers read
--------------------------------------------
  A  ITEM_DESCRIPTION            read  - the key
  B  Avg Buy Price (New)         read  - the price used everywhere
  C  3 Years Old 65% of cost     not read (plain values in the master;
                                 formulas on B in the legacy file)
  D  5 Years Old 50% of Cost     not read (same)
  E  10+ Years Old 30% of Cost   not read (same)
  F  Source to Buy               read  - printed on the tooling pages

Yes, "cost" is lower case in C and capital in D and E. Leave them as
they are; nothing reads them, so nothing minds.

Who reads it and what it feeds
------------------------------
  Every reader asks ampol_master.locate for the pricing list and is
  handed the master's Pricing tab when the master exists, else the
  legacy file. Then:

  Tooling reports (button 04)   build_ampol_tooling_report.load_all
    Opens the tab by its name Pricing (the legacy sheet by its name
    RENTAL_STOCK). Reads A, B and F by HEADER text; falls back to
    columns A, B and F by position only if a header is not found.
    Replacement value on the on-hire register; buy price and where to
    buy on the utilisation and what-to-buy pages.
  Stocktake engine (button 05)  build_stocktake_compliance_tool
    .load_pricing - opens the tab by name (the legacy file's FIRST
    sheet). Needs the headers ITEM_DESCRIPTION and Avg Buy Price (New)
    exactly, or it stops. Reads by header only, never by position.
  Radio report (button 03)      build_radio_report.load_prices
    Opens the tab by name (the legacy file's FIRST sheet). Finds
    ITEM_DESCRIPTION and Avg Buy Price (New) by HEADER; only when a
    header is absent does it take column A and column B by position.
    Also needs the rows AMPOL MOTOROLA RADIO and AMPOL MOTOROLA RADIO
    BATTERY as the fallback price for a radio or battery whose SiteIQ
    description carries a serial number.
  Check - two readers still ask for the legacy FILE by name, not for
    the tab: txn_insights.load_all (the value figures on the insight
    pages of every family report) and build_stocktake_house_style.main
    (the script button 05 actually runs). On a laptop where button 16
    has parked the legacy file they find no prices at all. That needs
    a code change; until it is made a price typed into the tab does
    not reach those pages.

How a price is matched
----------------------
  By the description text, whole, after cleaning: spaces collapsed to
  one, upper-cased (the stocktake engine also flattens umlauts; the
  tooling report reads the former site name as Ampol first). So
  1/2 DRIVE SOCKET and 1/2" DRIVE SOCKET are two different items, and
  a description that is not on this list is simply unpriced.

  Duplicates - a description listed more than once:
    tooling report and radio report  - the FIRST row down the sheet
    stocktake engine and txn_insights - the most common price; a tie
                                        takes the lower; every conflict
                                        is listed on the Pricing Gaps
                                        tab of the count worklist.
  On 03 Sep 2026: 273 descriptions are listed more than once (831
  repeat rows) and 11 of them carry two different prices.

You may freely
--------------
  - change any price in B (as a plain number)
  - change or fill in the text in F
  - add rows, anywhere
  - add new columns to the RIGHT of F
  - edit or ignore C, D and E
  - change colours, widths, filters, freeze panes
  - move the Pricing tab to another place in the tab order (every tab
    is opened by its name, never by its position)
  - edit the text on the Read me tab

You must not - and what breaks if you do
----------------------------------------
  1. Rename the tab "Pricing" - or any other tab.
       ampol_master.locate looks for the tab by that exact name. Not
       found, it looks for the legacy Ampol_ToolStore_Pricing.xlsx in
       Data\SiteIQ, Data\Editable and the Data root - never in
       Data\_Archive_workbooks, where button 16 parked it. If a legacy
       copy is still lying there, its prices (possibly out of date)
       are used and nobody is told. If not, every reader runs with no
       prices: tooling and stocktake values gone, every radio and
       battery TBC. The same rule sends a renamed Descriptions, Gas
       serials or Radio serials tab back to its own legacy file, else
       to nothing.
  2. Rename the workbook so that it no longer starts with
     Ampol_Master, or move the list to another workbook.
       The master is found by the pattern Ampol_Master*.xlsx. Not
       found, every tab falls back as in 1 - all four lists at once.
       A list moved to another workbook is not looked for anywhere.
  3. Delete or rename the other tabs - Descriptions, Gas serials,
     Radio serials. Each feeds a report; 1 applies to each.
  4. Put anything above the header. Row 1 must be the header.
       A title row becomes the header: the stocktake engine stops on a
       missing header; the tooling and radio readers see a header
       where the first item should be and every price is lost.
  5. Change a header spelling (ITEM_DESCRIPTION, Avg Buy Price (New),
     Source to Buy) - capitals, spaces and brackets included.
       Stocktake engine stops. Tooling and radio readers silently fall
       back to column position. Extra spaces at the end are tolerated;
       do not rely on it.
  6. Move, insert or delete a column so that A or B no longer holds
     what its header says.
       The headers are what the readers look for, so a column that
       moves together with its header still reads. Position is only
       the fallback, used when a header cannot be found - and then the
       tooling and radio readers take A, B (and F) blind. Keep A and B
       where they are anyway, so the fallback is right if a header is
       ever mistyped.
  7. Change the key column. A is the description the SiteIQ export
     uses, matched whole. Retyping a description so it "reads better"
     breaks its match - the item becomes unpriced.
  8. Type a price as text - a dollar sign in front, "ea" after it,
     "TBC", "n/a", or a cell formatted as Text.
       Treated as blank: the item prints a dash and is left out of
       every value total. The cell must hold a number; the currency
       format Excel shows is fine.
  9. Type a zero for an unknown price.
       The stocktake engine treats 0 as unpriced; the tooling report
       may carry it through as a price - check. Leave the cell blank.
 10. Merge cells. None are merged today. A merged header or a merged
     block in A or B leaves blank cells where the readers expect a
     description and a price.
 11. Add extra header rows, group headings or subtotal rows inside the
     list. A subtotal row is read as an item called "Total" with a
     price; a blank-description row is skipped, but a heading row with
     text in A and nothing in B is an unpriced item.
 12. Use a formula in B that leaves text. The readers take the value
     Excel last saved. A formula that returns "" (empty text) reads as
     text - unpriced. A formula never calculated and saved by Excel
     reads as blank. A formula that returns a number is fine, but a
     plain number is safer.
 13. Sort the list while duplicates remain. Sorting is harmless unless
     a description is listed twice with two prices - then the tooling
     and radio reports may print the other value. Remove the
     duplicate instead; the Pricing Gaps tab lists them.
 14. Delete the AMPOL MOTOROLA RADIO or AMPOL MOTOROLA RADIO BATTERY
     rows. The radio report loses its fallback price for
     serial-numbered radios and batteries: printed as TBC.
 15. Save as .xls or .csv, or from a tool that does not keep the .xlsx
     format. The readers open .xlsx only.
 16. Put the legacy file back in Data beside the master. It is ignored
     while the master has its Pricing tab (the master wins), button 10
     warns that it is still in Data, and button 16 parks it again.
     Edit the tab, not the old file.

On a laptop still on the legacy file
------------------------------------
  Until button 16 has been run there is no master, and the same rules
  apply to Ampol_ToolStore_Pricing.xlsx, plus three of its own:
  - keep the file name - the tooling report tries
    Ampol_ToolStore_Pricing.xlsx, then Ampol ToolStore Pricing.xlsx,
    then Ampol_ToolStore_Pricing*.xlsx; the stocktake and radio
    readers match *Pricing*.xlsx and may pick up a wrong file
  - keep RENTAL_STOCK as the one and only sheet - the tooling report
    opens it by that name; the stocktake and radio readers take the
    first sheet, whatever it is called
  - keep it in Data (the root, Data\SiteIQ or Data\Editable are all
    searched; Data\_Archive_workbooks is not)
  Button 16 then builds the Pricing tab from it - every row, values
  only, nothing invented - and parks it.

Before handing it back
----------------------
  - Tab named Pricing.  Row 1 = the six headers above.  The other
    tabs untouched.
  - Column B: numbers only, blanks for unknown, no zeros, no text.
  - No merged cells, no rows above the header, no subtotal rows.
  - Close the file, then run 10_CHECK_MY_SETUP and the report you
    changed prices for. The radio report's console says where the
    prices came from - "Pricing master : Data\Editable\
    Ampol_Master.xlsx [Pricing]" - and every reader says in plain
    words when it found no pricing list at all.
