# Ampol tool store reporting suite - Excel files the reports read

Ampol tool store reporting suite - Excel files the reports read. Author: Andrew Fisher | POWERED BY SITEIQ. As at 03 Sep 2026 (suite v1.13).

## Who this is for

Anyone who opens, edits or hands over one of the Excel files in the suite's Data folder (Data\SiteIQ and Data\Editable) - including another AI tool asked to tidy one up. Every sheet name, header and rule below was read from the Python code or from the workbook itself on 03 Sep 2026. Nothing is assumed. Where something could not be confirmed it says "check".

The reports only read these files. They never write to them. Three scripts do write into Data, and only these: button 12 copies the SiteIQ exports in; button 16 (tidy_data_folder.main) builds Ampol_Master.xlsx once from the legacy files and leaves a master that already exists alone; button 05 rewrites store_layout.template.json on every run.

The only figures in this document are row counts, taken on 03 Sep 2026. "Data rows" means the rows under the header.

## How a report finds a file

- Since v1.13 (03 Sep 2026) there are two folders under Data (ampol_paths.siteiq_dir, ampol_paths.editable_dir):
  - Data\SiteIQ holds the three SiteIQ pulls - RENTAL_STOCK.xlsx, TRANSACTIONS.xlsx and STOCKTAKE.xlsx. Button 12 files them there (PULL_SITEIQ_EXPORTS: DEST = ampol_paths.siteiq_dir()) and parks the copy it replaces, date-stamped, in Data\SiteIQ\previous (ampol_paths.previous_dir). Nothing in this folder is ever hand-edited.
  - Data\Editable holds what Andrew maintains - Ampol_Master.xlsx (descriptions, pricing and the two serial lists in one workbook), Ampol_Calibration_Register.xlsx, Rigging Register.xlsx, and store_layout.json with its template.
  - Data\_Archive_workbooks holds parked files - the three old .xlsm workbooks (button 14) and the legacy files the master replaced (button 16). No report reads from it.
- A report asks for a file by pattern (ampol_paths.find_data, ampol_paths.find_data_all). The search runs through Data\SiteIQ, then Data\Editable, then the Data root itself (ampol_paths.data_dirs - only the folders that exist). Every one of those folders is searched for the pattern and the newest hit across all of them wins. Sub-folders such as previous and _Archive_workbooks are never searched. Excel lock files (names starting with ~$) and archived pulls (names starting with Source_) are never candidates. So most files may carry a suffix - RENTAL_STOCK (1).xlsx still matches RENTAL_STOCK*.xlsx.
- Because the Data root is still searched, a laptop that has not run button 16 keeps working with every file where it was. The other side of that: a second copy left in the Data root beside the tidied one is a candidate too, and whichever of the two was saved more recently is the one read.
- Exception - the tooling reports (button 04, build_ampol_tooling_report.load_all) ask for the SiteIQ files by exact name, no wildcard: RENTAL_STOCK.xlsx, TRANSACTIONS_Full.xlsx or TRANSACTIONS.xlsx, and STOCKTAKE.xlsx or STOCKTAKE (1).xlsx. A renamed export stops button 04 ("RENTAL_STOCK.xlsx not found in the Data folder") while the other buttons still run. The exact-name rule no longer applies to the mapping and pricing lists - those come from the master (below).
- The master workbook. Every reader of the descriptions, prices and serial lists asks ampol_master.locate(kind, legacy patterns) and gets back a (path, sheet) pair. If Ampol_Master*.xlsx is found (ampol_master.path, through find_data) and it carries the tab for that kind (ampol_master.SHEETS: Descriptions, Pricing, Gas serials, Radio serials), the answer is the master and that tab. Otherwise the newest legacy file matching the patterns is returned with no sheet, and the reader applies its own old sheet rule. If neither exists the answer is empty and the reader degrades in plain words on the console. The readers that do this: gasmon_engine.load_serials, ampol_serials.load, build_radio_report.main (feeding build_radio_report.load_serials and build_radio_report.load_prices), build_ampol_tooling_report.load_all (mapping and pricing) and build_stocktake_compliance_tool.main (feeding build_stocktake_compliance_tool.load_corrections and build_stocktake_compliance_tool.load_pricing). The console line from ampol_master.describe reads, for example, "Data\Editable\Ampol_Master.xlsx [Pricing]" (build_radio_report.main and build_stocktake_compliance_tool.main print it).
- Two readers do not go through ampol_master.locate yet - build_stocktake_house_style.main (the script button 05 runs) and txn_insights.load_all still look for the legacy names. See "Things to check".
- The earlier pulls. ampol_paths.previous_dirs lists both Data\SiteIQ\previous and the pre-v1.13 Data\previous, so the pull-against-pull pages (pull_diff.find_previous_pull) and the verify gate (VERIFY_NUMBERS.count_everything) find an earlier RENTAL_STOCK copy in either.
- Button 10 (CHECK_MY_SETUP) lists every expected file, says whether it was found and in which folder, and says what degrades without it. It prints a "Data layout" line (two-folder layout, or single Data folder - run 16_TIDY_DATA_FOLDER when ready). Once the master exists it marks each legacy file "not needed - the master workbook carries it", and warns if a legacy file is still sitting in Data beside the master.
- Button 16 (tidy_data_folder.main, 16_TIDY_DATA_FOLDER.bat) is the one-off move: it makes the two folders, moves the SiteIQ exports and the old Data\previous into Data\SiteIQ, moves the calibration and rigging registers and the store layout into Data\Editable, builds Data\Editable\Ampol_Master.xlsx from the legacy files (ampol_master.build - values only, every row kept) unless a master already exists, and parks the legacy files in Data\_Archive_workbooks with a dated line in WHY_THESE_ARE_HERE.txt. Moves only - nothing is deleted, and a name clash parks the older copy with a date stamp rather than overwriting. Safe to run twice; the second run reports nothing left to tidy. Buttons 05 and 12 create the two folders on their own, so seeing them does not mean 16 has been run - the master workbook does.
- Every reader opens the file with openpyxl in read-only mode and takes cached values (data_only=True). A formula cell is therefore read as the value Excel last calculated and saved. A formula typed in by a tool that does not calculate, or a file saved without recalculating, reads as blank.
- Two small lists are read by every report, not just their own: the Gas serials and Radio serials tabs of Ampol_Master.xlsx (or the two legacy serial files) feed the serial printed in brackets after a gas monitor's or radio's name on every page (ampol_serials.load, read once per run, display only).
- Every reader treats row 1 of a data sheet as the header row. There is no searching for the header lower down (the one exception is the rigging workbook's Extracted Register sheet, noted below).
- The three old .xlsm workbooks (Ampol Gas Monitor Report, Ampol_Radio_Report, Ampol_Onhire_Tooling_Report) are not read by any report and are parked in Data\_Archive_workbooks by button 14 (archive_old_workbooks.main, which looks in the Data root only). If Ampol_Onhire_Tooling_Report.xlsm is still in Data, the tooling report opens it only to print a console cross-check (build_ampol_tooling_report.workbook_crosscheck); no page takes a number from it.

## Part A - the SiteIQ exports (never hand-edited) - Data\SiteIQ

Three files. They are exported from SiteIQ, land in Downloads, and button 12 (PULL_SITEIQ_EXPORTS.main) files them into Data\SiteIQ:

- It opens each Excel file in Downloads and identifies the export by its data sheet name - RENTAL_STOCK, STOCKTAKE or CUSTOMER_CONTRACTOR_EQUIP - never by the file name (PULL_SITEIQ_EXPORTS.inspect).
- It checks the export is this site's: a PROJECT or PROJECT SCHEDULE cell on REFERENCE_INFO must contain "ampol" or "lytton", or the first rows of the data must (PULL_SITEIQ_EXPORTS.site_in_rows). Another site's file is skipped and named on screen.
- Newest wins, by the export's own REQUESTED_DATE/TIME, not the file date.
- The copy already in Data\SiteIQ is backed up first to Data\SiteIQ\previous as YYYYMMDD_HHMM_RENTAL_STOCK.xlsx (and likewise for the other two); the stamp is when that older file was saved. Nothing is deleted. Before v1.13 the backups went to Data\previous; button 16 moves them across, and the readers look in both folders.
- These files are never edited by hand. If one is opened in Excel, close it without saving before running a report. Never sort, filter, retype or "clean" an export - the previous copies in Data\SiteIQ\previous are the proof of what SiteIQ said on the day.

Every export carries a REFERENCE_INFO sheet: row 1 holds headers, row 2 holds the values. The readers look for the header that contains REQUESTED_DATE and read the cell under it as "dd/mm/yyyy hh:mm AM/PM". That is the "Data as at" stamp printed on every page (pull_diff.reference_pull_time, gasmon_engine.load_rental_stock, build_ampol_tooling_report.reference_info, build_calibration_report.load_rental_stock, build_rigging_report.load_live, build_radio_report.load_from_register). If the stamp is missing, the file's saved time is used and the page says so.

## Part B - the workbooks Andrew maintains - Data\Editable

These are typed in by hand and are the ones most at risk from a well-meant tidy-up. Each section says what may be edited freely and what must stay.

### Ampol_Master.xlsx - the one editable workbook

A separate one-page note for whoever reviews the Pricing tab is in Docs\PRICING_FILE_DO_NOT_CHANGE.txt.

- File name and pattern: Ampol_Master.xlsx in Data\Editable (ampol_master.MASTER_NAME). Found by Ampol_Master*.xlsx (ampol_master.MASTER_PATTERNS, through ampol_paths.find_data - so it is also found in the Data root on a laptop where it was copied there).
- Maintained by: Andrew, in place. Built once by button 16 (ampol_master.build) from the legacy files - values only, never a formula, every row of every source kept, nothing invented. A master that already exists is never rebuilt or touched by any button.
- Tabs (ampol_master.SHEETS, opened by name - the order of the tabs does not matter): Read me, Descriptions, Pricing, Gas serials, Radio serials. Row counts on 03 Sep 2026: Descriptions 3,415; Pricing 3,227; Gas serials 1,202; Radio serials 706.
- Header row: row 1 on every tab, with the headers listed under each tab (ampol_master.HEADERS) - the legacy files' headers, unchanged, so every reader keeps the column names it always had. Each tab has the header row frozen and an autofilter; there are no Excel tables and no merged cells.
- Which tab each report reads, and what happens when a tab is missing: ampol_master.locate opens the workbook and checks the tab name is present. A tab that is missing or renamed sends that one reader back to its legacy file (searched in Data\SiteIQ, Data\Editable and the Data root - not in Data\_Archive_workbooks, where button 16 parks them). On a tidied laptop that legacy file is not there, so the reader runs with nothing: no corrections, no prices, or no serials, as the sections below say. The other tabs keep working.
- May be edited freely, on every tab: adding rows anywhere; adding columns to the right of the last header; column widths, colours, filters, freeze panes; the Read me text; the order of the tabs.
- Must not change (and what breaks): the file name (a renamed workbook is not found - every reader falls back to its legacy file if one is still in Data, else runs with nothing); the five tab names (a renamed tab does the same for that one reader); moving a list to another workbook (same); the header row being row 1; the header spellings on each tab; no merged cells; no title rows. Do not put a legacy file back in Data beside the master - it is ignored while the master has the tab, button 10 warns about it, and button 16 parks it again.

### Descriptions tab - barcode to corrected description

Replaces Tooling_Description_Mapping.xlsx (the tooling report's mapping) and New_Descriptions___Andrew.xlsx (the stocktake's corrections) - one list, read by both.

- Header row 1, exact header text: ITEM_DESCRIPTION, ITEM_BARCODE, Corrected Description, Correction Notes, Changed?. 3,415 data rows.
- How button 16 built it (ampol_master.build): every row of the mapping's Use this sheet (or In use, or CorrectedDescriptionsTable), keyed by barcode, first row wins; Correction Notes and Changed? joined on from New_Descriptions___Andrew.xlsx by barcode; a barcode only in New_Descriptions is appended. Where the two files gave a barcode different corrected text, Andrew's (New_Descriptions) text was kept and the mapping's went into Correction Notes as "[mapping had: ...]" - one row carries that note on 03 Sep 2026. Rows with a blank barcode were dropped. Every barcode appears once. Changed? reads Yes on 1,401 rows, No on 46 and is blank on 1,968 (the rows that were only in the mapping).
- Key column: ITEM_BARCODE, upper-cased.
- Readers:
  - build_ampol_tooling_report.load_all (button 04): opens the tab by name; finds ITEM_BARCODE and Corrected Description by header (CorrectedDescriptionsTable.Corrected Description is also accepted for the second) - if either is not found the report silently runs with no corrections and prints "mapping coverage TBC". Where a barcode appears twice the first row wins. ITEM_DESCRIPTION feeds one extra rule - when every row carrying the same raw description agrees on one corrected name, that name is also shown for other barcodes with that raw description (display only). Correction Notes and Changed? are not read - a row switched off with Changed? = No still corrects the tooling register.
  - build_stocktake_compliance_tool.load_corrections (button 05's engine, through build_stocktake_compliance_tool.main): opens the tab by name; needs ITEM_DESCRIPTION, ITEM_BARCODE and Corrected Description or the report stops; Changed? is optional. A row is skipped when Corrected Description is blank or Changed? is "No"; a blank Changed? is accepted. Where a barcode appears twice the last row down the sheet wins. Two maps are built: barcode to corrected description (exact, wins), and old description to corrected description, used only where every row with that old description agrees. Correction Notes is not read. Note: the script button 05 actually runs, build_stocktake_house_style.main, still looks for New_Descriptions*.xlsx - see "Things to check".
- What it feeds: the corrected description on the tooling on-hire register and the grouping of the utilisation and what-to-buy pages (an item with no corrected description is not in the utilisation figures); the description on the stocktake worklist, compliance and team reports, the priority tier decided on the corrected description, and the stocktake price lookup, which also tries the corrected description.
- Blank cells: blank Corrected Description - no correction for that barcode (the tooling report also lets the row feed its by-description rule only when it has a corrected text). Blank ITEM_BARCODE - the tooling report uses the row for the by-description rule only; the stocktake uses it for the old-description map only. Blank Changed? - treated as yes.
- May be edited freely: Correction Notes; ITEM_DESCRIPTION; setting Changed? to No to switch a row off for the stocktake; adding rows; columns to the right of Changed?.
- Must not change (and what breaks): the tab name Descriptions (the tooling report falls back to Tooling_Description_Mapping.xlsx and the stocktake engine to New_Descriptions___Andrew.xlsx, if they are still in Data - else no corrections at all); the header spellings (ITEM_BARCODE or Corrected Description missing - the tooling report silently corrects nothing; any of the first three missing - the stocktake engine stops); header row 1; no merged cells. Keep each barcode on one row - the two readers pick different rows when a barcode is listed twice.

### Pricing tab - the pricing list

Replaces Ampol_ToolStore_Pricing.xlsx (its one sheet, RENTAL_STOCK). The one-page reviewer's note is Docs\PRICING_FILE_DO_NOT_CHANGE.txt.

- Header row 1, exact header text: ITEM_DESCRIPTION | Avg Buy Price (New) | 3 Years Old 65% of cost | 5 Years Old 50% of Cost | 10+ Years Old 30% of Cost | Source to Buy. (The lower-case "cost" in the third header and the capital "Cost" in the fourth and fifth are how the legacy file was and how the tab is; only the first, second and sixth headers are read.) 3,227 data rows - every row of the legacy sheet, copied by header. The three aged-price columns, formulas in the legacy file, are plain values in the master (button 16 copies values only).

## Rules for anyone editing these files

1. Never edit a SiteIQ export (RENTAL_STOCK, TRANSACTIONS, STOCKTAKE) in Data\SiteIQ. If you opened one, close it without saving. Button 12 replaces them; Data\SiteIQ\previous keeps the old ones.
2. Keep the file names. The tooling report (button 04) needs the exact names for the three exports; Ampol_Master.xlsx is found by Ampol_Master*.xlsx and a renamed master is simply not found. The rest match by pattern, and a stray extra file matching the pattern - in Data\SiteIQ, Data\Editable or the Data root - can be picked up as the newest.
3. Keep the tab names in Ampol_Master.xlsx (Descriptions, Pricing, Gas serials, Radio serials) - each reader opens its tab by name and falls back to a legacy file, or to nothing, without it. Do not move a list to another workbook. The order of the tabs does not matter. On a laptop still on the legacy files, keep those sheet names and keep each list on the first sheet - the pricing list, the New_Descriptions list and the radio register are opened by name or as the first sheet, and a new sheet in front of them is read instead.
4. Row 1 is the header. No title rows, no notes above the header, no blank row 1.
5. Keep the header spellings exactly, including capital letters, spaces and punctuation (Certificate No. with its full stop; SKU/ITEM DESCRIPTION with a space; Avg Buy Price (New) with its brackets). Extra spaces at the end of a header are tolerated by most readers, but do not rely on it.
6. Do not move columns A and B on the Gas serials or Radio serials tabs (or the legacy serial files) - those readers use the position, not the header. On the Pricing tab the headers are what the readers look for; column position is only their fallback when a header cannot be found, so keep A and B where they are anyway.
7. Numbers as plain numbers. A price cell holds the number only - no dollar sign in front, no "ea" after it, no "TBC". A blank means unknown; a zero is not a price.
8. Dates as Excel dates or as dd/mm/yyyy text. Never a US date. Never a month name in a date column.
9. No merged cells anywhere. None of the files has any today.
10. Formulas only if Excel calculated and saved them, and only if the result is a number where a number is expected. A formula that leaves "" (empty text) in a price cell reads as text, so the item is unpriced.
11. Add rows freely, at the bottom or anywhere. Add new columns to the right of the last one. Never insert a column on the left of, or between, the columns the code reads.
12. Remove duplicates rather than sorting around them: on the Pricing tab a description listed twice with two prices gives the tooling and radio reports the first one down the sheet; on the Descriptions tab a barcode listed twice gives the tooling report the first row and the stocktake the last.
13. Close the file before running a report. A file open in Excel leaves a ~$ lock file (ignored) and can block reading (button 10 says so).
14. Never save one of these as .xls, .csv or a Google Sheet export renamed to .xlsx. The readers open .xlsx only.
15. Once Ampol_Master.xlsx exists, edit it - not a legacy file. A legacy file put back in Data is ignored while the master has the tab, button 10 warns about it, and button 16 parks it again in Data\_Archive_workbooks. Nothing in Data\_Archive_workbooks is read.
16. If you are not sure, run button 10 (check my setup) and then the report, and read the console: every reader says in plain words what it could not find, and the radio and stocktake consoles name the file and tab the prices and serials came from.
