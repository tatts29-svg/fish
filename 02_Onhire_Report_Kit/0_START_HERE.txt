   FIRST TIME ON THIS LAPTOP?   Do STEP 1 once.
   EVERY DAY AFTER THAT?        Start at STEP 2.


   STEP 1   Double-click       1_CHECK_THIS_LAPTOP.bat
   ------   ONCE, on a laptop that has never run this before.

            It builds nothing and changes nothing. It just tells
            you, in plain words, whether this laptop can run the
            report - and if it can't, the ONE thing to fix.

            If it says READY, go to step 2.
            If it says Python is missing, double-click
            3_GET_PYTHON_NO_ADMIN.bat and then press 1 again.


   STEP 2   Put today's exports in the Data_SiteIQ folder
   ------
            Pull these three out of SiteIQ and save them into
            Data_SiteIQ, straight over the top of yesterday's:

                 RENTAL_STOCK
                 SALES_STOCK
                 TRANSACTIONS   - pulled FROM THE START OF THE SHUT

            STOCKTAKE as well if you have it - not required.

            Why the wide TRANSACTIONS pull: every item on hire is
            dated from the day its issue transaction started, not
            from the stock record. If the transaction isn't inside
            the window you pulled, that item comes out UNDATED (the
            report says so, and why). Pull from the shut start and
            every item dates.

            DON'T RENAME THEM. SiteIQ's own long file names are
            fine (RENTAL_STOCK_10_08_2026 06_05 AM.xlsx). If there
            is more than one, the newest is used.


   STEP 3   Double-click       2_MAKE_THE_REPORT.bat
   ------
            A black window opens, counts the tabs out and says how
            many pages the company pack ran to. Ten seconds. When it
            stops, close it.

            If something is wrong it tells you in plain words what
            to fix. It never builds half a report.


   STEP 4   Open the three things it just made
   ------
            THE EMAIL, in Reports\<today>\ :

                 <Job> On-Hire Report - <date>.eml

            Double-click it. It opens in Outlook as a DRAFT with
            the whole report laid out in the body and BOTH the
            workbook and the company pack already attached. Put the
            addresses on, read it, press Send.

            NOTHING SENDS BY ITSELF. Ever.

            THE WORKBOOK, in this folder:

                 <Job>_Onhire_Workbook_LATEST.xlsx

            Always the newest, always the same name - so a
            shortcut to it on the desktop never goes stale.
            Start on the Cover tab.

            THE COMPANY PACK, in Reports\<today>\ :

                 <Job> On-Hire Report by Company - <date>.pdf

            A cover with the headlines and a contents list, then a
            section for every company: their people, their gear,
            the day each item was issued. Click a company on the
            contents page and it jumps there. The same sections are
            saved one-per-company in Reports\<today>\By_Company\
            for forwarding a company just their own page.


   That's the whole job. There is no step 5.

   OPTIONAL      4_MAKE_OUTLOOK_DRAFT.bat
   --------
            The .eml opens as a draft on its own. Press 4 instead
            when you want the same email as a NATIVE Outlook draft -
            the kind where the To field searches the address book.
            Needs Outlook on the computer. Still nothing sends itself.


 IT DIDN'T WORK - FIND YOUR MESSAGE HERE
 =======================================

   Whatever the black window said, it is one of these. Nothing on
   this list needs IT, an install, or a phone call to Andrew.

   "YOU ARE RUNNING THIS FROM INSIDE THE ZIP"
        Right-click the zip, Extract All, pick Desktop, and press
        the button in the folder that appears. Ten seconds.

   "SOME OF THE KIT IS MISSING FROM THIS FOLDER"
        Same fix. Something got left behind in the zip. Extract the
        whole thing again.

   "PYTHON IS NOT ON THIS COMPUTER"
        Double-click 3_GET_PYTHON_NO_ADMIN.bat. It puts a private
        copy inside this folder. No admin rights, nothing installed
        on the computer, nothing else changed.

   "THE PYTHON ON THIS COMPUTER IS TOO OLD"
        Same fix - 3_GET_PYTHON_NO_ADMIN.bat.

   "These exports are not in Data_SiteIQ"
        Go back to step 2. The file names have to start with
        RENTAL_STOCK, SALES_STOCK and TRANSACTIONS.

   "... is a <other job> export but the others are <this job>"
        Two jobs' exports are mixed in Data_SiteIQ. Take the odd
        one out. This check exists so wrong numbers never go in
        front of a customer.

   "Windows won't let me write the workbook"
        The workbook is open in Excel. Close it and press the
        button again. Nothing is lost.

   "Windows protected your PC" (a blue box, before anything runs)
        Windows being cautious about a file that came off the
        internet. Click "More info", then "Run anyway". Or
        right-click the ZIP first, choose Properties, tick
        "Unblock", press OK, and extract it again.

   "This program is blocked by group policy" or
   "The command prompt has been disabled by your administrator"
        This one IS your IT department, and nothing in the kit can get
        round it. Ask them to allow this folder, or the simplest fix of
        all: Andrew runs the report on his laptop and emails you the
        finished .eml and workbook. You do NOT need any of this just to
        read or send the report.

   "cannot access the file" ON A FILE YOU CAN PLAINLY SEE
        A OneDrive file that hasn't actually downloaded. Right-click it,
        choose "Always keep on this device", wait for the green tick.

   THE WINDOW FLASHES AND DISAPPEARS
        You're double-clicking build_onhire_workbook.py instead of
        the button. Use 2_MAKE_THE_REPORT.bat.

   ANYTHING ELSE
        Double-click 1_CHECK_THIS_LAPTOP.bat and email Andrew the
        LAPTOP_CHECK.txt file it writes next to itself. That file
        answers every question he would have asked you.


 WHAT'S IN THE EMAIL - and what isn't
 ====================================

   Where we sit today   the position in two lines, before any table,
                        and four flags that say their status in words
   What is attached     the workbook and the pack, named
   The position         six headline numbers
   Who is holding gear  every company, what they hold, how long
   Working hardest      the gear earning its keep, and what to do
   Not moving           the biggest holdings that haven't gone out
                        at all - shelf space we're carrying
   Consumables to watch the lines running down
   Out the longest      oldest open issue transactions, worth a call
   Everything on hire   every company in A-Z order, every person under
                        them, and exactly what each one has got out
   What I need from you the actions, each with its own number

   NO COSTS. Not the labour, not the cost breakdown, not a rate and
   not a dollar sign anywhere in it - nor in the company pack. That
   is deliberate - the email is the operational picture and it can
   go to anyone. The money stays in the workbook.

   DATES. Every on-hire item is dated from the START of its issue
   transaction in SiteIQ, never from the stock record. An item with
   no issue transaction inside the TRANSACTIONS export you pulled is
   shown as UNDATED and the email says how many and why. The window
   the export covers is printed in the email footer, on the Cover
   and in the pack, so nobody has to guess.

   There are no pictures in the email and nothing it downloads, so
   it looks the same on the store laptop, in Outlook on a big
   monitor, and on a phone at the gate.

 THE COMPANY PACK - one PDF, a section for every company
 =======================================================

   The email tells everybody where the store sits. The pack is what
   you hand ONE company. It is written by coates_pdf.py, a small PDF
   writer that travels in this folder, so it comes out the same on
   any laptop with nothing installed - no Acrobat, no browser, no
   print driver. If it ever fails to build, the window says so in a
   band and the workbook and the email still go out without it.

   Page 2 of the pack is THE STORY - what the store did this period
   in plain words: the brief, the team at the counter and their hours,
   how gear is moving (same-day returns), stocktake discipline, the
   customer-owned gear logged through the counter, and the standards
   behind the numbers. Page 3 is LOOKING AHEAD while a shut is ahead
   or under way - the roster day by day (travel, mobilisation, day
   and night shifts), the milestones, when the counter is busiest by
   hour of day, what a day at the counter looked like last time, the
   tooling asked for most and the consumables that go fastest. Dates,
   people and movements only - never a dollar. Then AT A GLANCE - the
   store as pictures: the dials, who is holding gear, ratings,
   movements by day, what is working hardest and which consumables
   are running down. Every company section has an Items-by-person bar
   chart. All drawn in the Coates palette from the same numbers as
   the tables, as vectors - crisp at any size, on a phone or a wall.

   Open HOW_IT_WORKS.html for what is on each page.

 ===================================================================

 THE TWO TABS THAT ARE TYPED BY HAND
 ===================================

   Coates Labour and Cost Breakdown are not built from the exports -
   somebody types them. The refresh NEVER touches them, and neither
   of them appears in the email.

   Keep your working .xlsm in this folder and every refresh reads
   those two tabs out of it and writes them straight back, formulas
   and all. Your .xlsm is never written to.

   No .xlsm in the folder? Those two tabs come out empty with a note,
   ready to type into. Nothing breaks.


 THE JOB'S SETTINGS - JOB.txt and COMPANY_ALIASES.txt
 ===================================================

   JOB.txt carries the names and, under them, the job's settings:

      engagement: Fixed-rate tool store   the email and pack say so
      shutdown_end: 02/12/2026            countdown, and the gear-return
                                          push from four days out
      tidy_names: yes                     SHOUTING names made readable
      acronyms: MMG, BLA, GMS, B&S        left in capitals when tidying

   COMPANY_ALIASES.txt folds the spellings SiteIQ uses for one outfit
   (BELTECH = BELTEC, one per line). Only what is written there is
   folded - the kit never guesses that two names are the same company.


 A DIFFERENT JOB
 ===============

   Copy this folder, empty Data_SiteIQ, put the new job's exports in,
   press the button. It reads the job off the exports themselves, so
   it names itself correctly with nothing set up.

   Open JOB.txt only if you want to tidy up the names it uses.

   ONE JOB'S EXPORTS AT A TIME. If a Gladstone export ends up in a
   Weipa folder it stops and names the odd one out, instead of
   quietly building a report off two jobs mixed together.
