How the on-hire report works

One page. Three exports in — a workbook, an email and a company pack out.

Powered by SiteIQ  ·  Author: Andrew Fisher  ·  Shutdown Tool Store  ·  Nothing sends by itself

This folder is a tool, not a system. It reads the SiteIQ exports you put in front of it and writes one Excel workbook, one email draft and one PDF company pack. It sends nothing, changes nothing on site, and never needs the internet — the Excel library and the PDF writer it runs on both travel inside this folder, so there is nothing to install on a laptop that has never seen it.

3The emailThe position first, then the detail behind it

One white sheet, laid out to be read on a phone at the gate or a big monitor in the office. 4How things are datedThe transaction wins, every time

Every on-hire item is dated from the start of its issue transaction in SiteIQ — the day it actually went over the counter. It is never dated from the stock record's ON_HIRE_DATE. For most items the two agree to the day; where they don't, the stock record is the one that is stale, and it is what used to put “92 days” against gear that went out on Monday.

Pull TRANSACTIONS from the start of the shutdown. The export only carries transactions inside the date range you ask SiteIQ for. An item whose issue transaction is outside that window cannot be dated, so the report shows it as undated, says why, and lists the SiteIQ stock date beside it on the Detailed Onhire tab for checking. A transactions export pulled from the shut start dates every item — and the window it covers is printed on the cover, the email footer and the pack.

5The company packOne PDF, a section for each company

The email tells everybody where the store sits. The pack is what you hand one company: their people, their gear, the day each item was issued, and the consumables they have drawn this period. It opens on a cover with the headlines and a contents list — click a company and it jumps to their section; every company is also a bookmark down the side of Acrobat.

It is written by coates_pdf.py, a small PDF writer that travels in the kit, so it comes out identical on any laptop with nothing installed — no browser, no print driver, no Acrobat needed to make it. It is set in Inter, a typeface that travels in the kit's _fonts folder; only the characters a pack uses are embedded, so files stay small and every chart is a vector, as sharp on a wall screen as on a phone. The dark bands — the cover hero, the dials card, each company’s section header and the footer on every page — are Coates charcoal and near-black with white type, so the numbers land first; small orange text on white uses a deeper orange that stays readable, while the wordmark, rules and bars keep the brand orange. Without the folder the pack still builds, in Helvetica. If the pack ever fails to build, the window says so in a band and the workbook and email still go out without it.

Every tab carries the Coates title band, a filter, frozen headings, and prints landscape on A4 with the headings repeated, the job and as-at time in the page header, and the page number down the bottom. Ratings, statuses and day counts are coloured by Excel's own conditional formatting, so the colour follows the value if anybody sorts or retypes a cell.

The two tabs nobody should overwrite

Coates Labour and Cost Breakdown are not built from the exports. Somebody sits down and types them, and there is no way to rebuild that from SiteIQ. So the refresh never touches them. It reads them out of the previous workbook — values, formulas, dates, times, exactly as they were — and writes them back. Your original .xlsm is never written to.

Type into <Job>_Onhire_Workbook_LATEST.xlsx. That is where the two hand-typed tabs are read from on every refresh and written straight back. An old .xlsm in the folder is read only on the very first run, before a LATEST exists; a roster from a previous shut is replaced once, with a note, by the job’s seed. Weipa and MMG start seeded; any other job starts the two tabs empty, headed and ready to type into.

7How the usage ratings are worked outPrinted on the Cover of every workbook, so nothing is taken on trust

Tooling is rated on TURNS — transactions divided by how many of that item are on site. One item that went out five times is working. Five items that went out once each are sitting there. Utilisation on its own cannot tell those two apart.

8Another computer, or another jobCopy the folder. All of it.

Another computer: copy the whole folder across — all of it, not just the button. Then press 1_CHECK_THIS_LAPTOP.bat once. It changes nothing; it just tells you whether that laptop will run the report, and if it won't, the one thing to fix.

There is nothing to install. The Excel library and the PDF writer travel inside the folder, so no pip, no internet, no company proxy to argue with and no IT ticket. The only thing the laptop supplies is Python 3, and if it hasn't got one, 3_GET_PYTHON_NO_ADMIN.bat puts a private copy inside this folder without admin rights. Excel and Acrobat are only needed to open what comes out, never to build it.

If you send this kit to somebody else, send the whole zip and tell them to right-click it and choose “Extract All” first. Double-clicking a button while it is still inside the zip window is the number one reason somebody reports back that it doesn't work. The kit spots that and says so, rather than failing silently.

Another job: copy the folder, empty Data_SiteIQ\, put the new job's exports in, press the button. Every SiteIQ export carries the project it came from, so the report names itself correctly with nothing set up. JOB.txt is only there if you want to tidy up the names it uses.

One job's exports at a time. If a Gladstone export ends up in a Weipa folder, the refresh stops and names the odd file out. It will not quietly build a report off two jobs mixed together.
